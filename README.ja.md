# OshiMakiKey Studio

[Русский](README.md) · [Беларуская](README.be.md) · [Українська](README.uk.md) · [Қазақша](README.kk.md) · [中文](README.zh.md) · **日本語** · [English (US)](README.en.md) · [English (UK)](README.en-GB.md) · [Deutsch](README.de.md)

**⬇ [インストーラー（x64/x86）またはポータブル版をダウンロード](https://github.com/Arkomiko/OshiMakiKey-Studio/releases/latest)**

**CH552 / CH57x** チップを使った中国製マクロキーボード（USB `1189:8890`、`1189:8840`、`1189:8842`、`1189:8850`、`514C:8850`、`514C:8851` など）を設定するポータブルプログラムです。キーは 3〜16 個、ロータリーノブは最大 3 個に対応します。
各キーとノブの各動作（左回転、押下、右回転）に次を割り当てられます。

- **キー** — ショートカット、または最大 5 回の押下の連続（`Ctrl + C` のあと `Ctrl + V`）
- **メディア** — 音量、一時停止、曲送り、明るさ、電卓、エクスプローラー、ブラウザーのボタン
- **マウス** — 左/右/中ボタンのクリック、ホイール（Ctrl/Shift/Alt 併用も可）
- **システム** — プログラムの起動、Web サイト、ファイル/フォルダー、テキスト入力、cmd コマンド、ロック、画面オフ、スリープ、シャットダウン、再起動

エディターでは各動作に印が付きます。

- **✓** — キーボードのメモリーに書き込まれ、プログラムがなくてもどのパソコンでも動作します。
- **⚙** — プログラムまたはバックグラウンドサービスが実行します。デバイスがサービスキー F13〜F24 を送り、残りはプログラムが行います。

動作はボタンからボタンへ**ドラッグ**できます（基板の図でも一覧でも可）。そのままドラッグすると移動、**Ctrl** を押しながらだとコピーです。移動先に既に動作がある場合は警告が出ます（チェックボックスで無効化できます）。

## 起動

バージョン **0.1.6b**。`OshiMakiKeyStudio.exe` はプロジェクトのルートにあります。.NET 8 Desktop Runtime が必要です。

すべては**ひとつのウィンドウ**で行われます。初回起動ウィザード、設定、書き込みチェック、「バージョン情報」は基板の表示の位置に開きます。別ウィンドウで開くのはキーモニターだけです。ページ、設定の項目、テーマの切り替えはなめらかなトランジションで切り替わります。

初回起動時には**ウィザード**が開きます：言語 → テーマ → 基板（ダイレクト形式の基板は書き込みチェック付き）。続いて各部分を強調して説明する**ウィンドウツアー**があります（**ヘルプ → 使い方**、F1）。

1. キーボードを **USB ケーブル**で接続します。
2. 左側でキーまたはノブをクリックし、右側で動作を選びます。
3. **「デバイスに書き込む」**（F5）を押し、キーボードのケーブルを**挿し直します**。
4. **「デバイス → キーモニター」**（F8）で確認します。デバイスが送るショートカットやメディアコマンド、それが割り当てられたボタン、ボタンを押していた時間が表示されます。

**モニターとプライバシー。** 基板を見るため、モニターはすべてのキーボードの入力を受け取ります。そのため他のデバイスのキー名は表示しません（「キーが押されました」とどのデバイスかだけを、モニターのウィンドウがアクティブな間だけ表示）。`monitor.log` には基板のイベントとプログラムの動作だけが記録され、通常のキーボードで入力した文字は記録されません。ウィンドウとログはどちらも**最新の 500 件**だけを保持するので、ボタンを押し続けてもメモリーやディスクを圧迫しません。

**ドラッグ＆ドロップ。** 動作は別のキーやノブの片側にドラッグできます。カーソルの下にある部分（左回転、押下、右回転）が強調され、ドラッグ中の動作の横に移動先が表示されます。

「デバイス接続済み」の下で、現在のプリセットがキーボードに書き込まれているかを確認できます。

## バックグラウンドサービス OMK_Studio-Service

プログラムを**閉じていても**音量や曲送りなど ⚙ の動作を使えるようにするには、バックグラウンドサービスをインストールします（**設定 → バックグラウンドサービス**）。方法は 2 つあります。

- **Windows サービス** — 「サービス」一覧に *OMK Studio Service* として表示され、Windows と一緒に起動します。サービスはキーボードや音声にアクセスできない独立したセッション 0 で動くため、サインインしたユーザーのセッションで**ヘルパー**（`--service` 付きの同じ exe）を起動し、サインイン、ロック解除、異常終了のたびに再起動します。インストールと削除では管理者権限を求められます（UAC ウィンドウ）。プログラムのフォルダーを移動した場合はサービスを再インストールしてください（設定画面で通知されます）。
- **管理者権限なしの自動起動** — 同じヘルパーが Windows へのサインイン時に `HKCU\...\Run` から起動します（「タスク マネージャー → スタートアップ」）。

ヘルパーは選択した**サービスのプリセット**を記憶し、プログラムが開いている間はサービスキーを譲ります。サービスのプリセットは設定、プログラムのトレイアイコンのメニュー、ヘルパー自身のトレイアイコンのメニュー（プログラムのウィンドウが閉じているときに表示）で変更できます。

**キーリピート。** キーを押している間、Windows はどのキーボードとも同じように入力を繰り返します。困る場合は **設定 → キー → 「キーを押している間はショートカットを繰り返さない」** をオンにしてください。ショートカットはプログラム（またはサービス）が押下ごとにちょうど 1 回だけ実行します。

## プログラムのフォルダー

プログラムはポータブルです。Windows のプロファイルには何も保存せず、すべて exe の隣に置かれます。

```
OshiMakiKeyStudio.exe
drivers/      基板の説明（*.json）：USB ID、書き込み形式、レイアウト、アイコンの色
themes/       テーマ（スキン）
  light/, dark/      標準：ライト 13 種とダーク 13 種（*.json）
  custom/            カスタム：*.json、*.ts、*.zip パッケージ、パッケージフォルダー（minecraft.zip 同梱）
language/     言語パック（*.json）：ru、be、uk、kk、zh、ja、en、en-GB、de
user_data/    ユーザーデータ — 更新時にも上書きされません
  settings.json      全般設定：テーマ、言語、ドライバー、自動起動…
  presets/*.json     プリセット — キーとノブの割り当て、1 つにつき 1 ファイル
  working.json       アクティブなプリセットの作業コピー（未保存の変更）
  monitor.log        キーモニターと書き込みチェックのログ（最新 500 件）
  diagnostics-*.log  書き込みチェックの記録（14 日間、最大 10 ファイル）
```

フォルダーは丸ごと移動できます（別のドライブ、USB メモリー、別のパソコンへ）。フォルダーの外に書き込むのは `HKCU\...\Run` の自動起動の項目と Windows サービスだけで、それも有効にした場合だけです。旧バージョンのテーマフォルダー `theme` も読み込まれます。

**プリセット。** アクティブなプリセットはウィンドウ上部で選びます。変更はすぐ作業コピーに反映され、プリセットファイルには **「保存」** ボタン（フロッピー、Ctrl+S）で書き込みます。同じ名前のファイルがある場合は、新しい名前を付けるか上書きするかを選べます。「⋯」メニューには「プリセットに名前を付けて保存…」「一覧を更新」「プリセットのフォルダーを開く」があり、その他は **ファイル** メニューにあります。

**テーマ**（**設定 → 外観**）。テーマと言語は**選んだ時点ですぐに**適用され、「キャンセル」で元に戻ります。標準テーマは共通のライトまたはダークの背景と 13 種のアクセント（赤、コーラル、オレンジ、アンバー、黄、ライム、緑、ティール、スカイ、青、バイオレット、パープル、ピンク）です。設定では折りたためる「標準」グループ内のアクセント色の丸として表示されます。その下に `themes/custom` のテーマのサムネイルが並ぶ「カスタム」グループがあります。

テーマは `{"id", "name", "order", "dark", "colors": {…}}` です。ファイルにない色は基本色（`window`、`surface`、`text`、`accent`）から導かれます。色の完全な一覧は任意の `themes/light/*.json` にあります。任意の項目：`corners`（角の丸み、0 で直角）、`background`（組み込みのアニメーションシーン、現在は `minecraft`）、`backgroundImage`（パッケージ内の背景画像）、`animationFps`（`animate` のフレームレート）。

カスタムテーマの形式：
- `*.json` — 標準テーマと同じ
- `*.ts` — TypeScript 構文の同じオブジェクト（`export default { id: 'my', colors: { accent: '#FF8800' } };`）。キーは引用符なし、文字列は単一引用符、コメントや末尾のカンマも使えます。ファイルはデータとして読み込まれます。
- `*.zip` またはフォルダー — パッケージ：`theme.ts`（または `theme.json`）と、`img`（画像：背景、シーンのテクスチャ）、`animate`（アニメーション背景のフレーム、名前順）、`scripts`（テーマのスクリプト）の各フォルダー

**テーマのスクリプト**（`scripts/*.js`）は組み込みの JavaScript **サンドボックス**（Jint）で実行されます。ファイル、ネットワーク、プロセス、.NET にはアクセスできず、呼び出しごとに時間、メモリー、再帰の深さが制限されます。止まったりエラーになったスクリプトは通知とともに無効化され、プログラムは動き続けます。スクリプトで使えるもの：

```js
theme.onFrame(function (g, t, w, h) { … });     // 毎フレーム、テーマの背景の上に描画（t は秒）
theme.addWindow({ title, menu, width, height,     // 独自のウィンドウ — 「ヘルプ」メニューの項目
                  onFrame(g, t, w, h), onClick(x, y) });
theme.hour(); theme.minute(); theme.log('テキスト');
// キャンバス g：rect(x, y, w, h, '#RRGGBB')、circle(x, y, r, 色)、line(x1, y1, x2, y2, 色, 太さ)、
//              text(文字列, x, y, 色, サイズ)、image('img 内の名前', x, y, w, h)、width、height
```

テーマに独自の背景がある場合、メインウィンドウのカード同士の隙間（そうしたテーマでは広めになります）、設定画面、「バージョン情報」に表示されます。同梱の **「Minecraft スタイル」** テーマ（`themes/custom/minecraft.zip`）は、直角の角、石と草の配色、**パソコンの時計に合わせた空**（昼は太陽と鳥、夕方はオレンジ色の地平線、夜は星と月とホタル）、雲とブロックの地形を備え、「ヘルプ」メニューにはテーマのスクリプトによる「作業台」ウィンドウがあります。パッケージは `tools/make-minecraft-theme.py` で作成します。

**言語**（**設定 → 言語**）：`{"code", "name", "strings": {キー: テキスト}}` 形式の `language/<コード>.json`。ロシア語はプログラムに組み込まれています。`ru.json` は `tools/lang-keys.ps1` でコードから生成され、このスクリプトは他の言語で不足しているキーも表示します。翻訳にキーがない場合はロシア語のテキストが表示されます。

**ドライバー**（**設定 → デバイス** または **デバイス → ドライバー**）：USB ID とメディアインターフェースの種類で自動的に選ばれます。基板が図と違う場合は、合うレイアウトを手動で選んでください。各ドライバーには、ファイルのレイアウトと色から描かれた専用のアイコンがあります。

**更新とファイル**（**ヘルプ → 更新とファイルを確認** または **設定 → ファイルとヘルプ**）：バージョンを GitHub の最新リリースと比較し、ドライバー、テーマ、言語のファイルがそろっていて読めるかを確認します。プログラム自体は何もダウンロードしません。新しいバージョンがあればダウンロードページを開けます。

**ファイルがない場合。** テーマ、言語、ドライバーをすべて削除すると、プログラムは組み込みの設定で動作し、上部の下に更新の確認を勧める通知を表示します。

## 基板と書き込み形式

| 形式 | 基板 | フレーム |
|---|---|---|
| ダイレクト | `1189:8890`、ビットマップ型メディアインターフェースの CH552（3 または 6 キー + ノブ） | `[ボタン] [修飾] 00 [コード1…コード6]`、最後に `AA AA` |
| k8890（ch57x-keyboard-tool） | `1189:8890`、メディアは 16 ビットコード | `03 FE …`、`03 [ボタン] [レイヤー/種類] …`、`03 AA AA` |
| 公式プログラム「バージョン 0」 | `1189:8890`、手動 | `[ボタン] 01 [個数] [番号] [修飾] [コード]`、各ボタンの後に `AA AA` |
| k884x | `1189:8840`、`8842`、`8850`、`8830`〜`8833`、`8810`、`514C:8851` — 3〜15 キー、ノブ最大 3 個 | `03 FE [ボタン] [レイヤー] [種類] …`、続いて `03 AA AA`、`03 FD FE FF`、`03 AA AA` |
| k8850（実機未確認） | `514C:8850`、4×4 グリッド | `03 FD [ボタン] [レイヤー] [種類] …`、続いて `03 FD FE FF` |

**ダイレクト形式の特定方法。** 段階的な診断の結果、ファームウェアはフィールドを解釈していないことが分かりました。フレームの先頭バイトがボタン番号で、続く 8 バイトはそのままキーボードの HID レポートとして保存されます。そのため `03` で始まるフレームはボタン 3 に入り、メディアは修飾キーに化けていました。これが [#168](https://github.com/kriomant/ch57x-keyboard-tool/issues/168) の「修飾キーのキュー」です。

ダイレクト形式の基板自体はボタンごとにショートカットを 1 つ保存します。メディア、マウス、連続入力、システム動作はプログラムが実行します（⚙）。CH552 6 キー + ノブのボタン番号：キー 1〜6 は 1〜6、ノブは左 11、押下 12、右 13。他のダイレクト形式の基板では **デバイス → 書き込みを確認…** がボタン 1〜30 にテスト用の文字（a〜z、続いて数字）を書き込み、各キーとノブを押すよう求めて、見つかった番号を記憶します。

## Windows のドライバーは必要？

不要です。このデバイスは標準的な USB HID デバイス（キーボード、マウス、メディア、プログラミング用のサービスインターフェース）です。プログラムは標準の `hid.dll` を通じてサービスインターフェースに設定を書き込みます。管理者権限も UsbDk/Zadig も不要です。プログラムの「ドライバー」とは `drivers` フォルダーにある基板の説明のことです。

```
デバイスのキー ──► デバイスがサービスキーを送る（F13…F24、Shift/Ctrl + F13…）
                                   │
                                   ▼
OshiMakiKey Studio またはサービスのヘルパー ── RegisterHotKey ──► メディア / マウス / 起動 / テキスト / …
```

## ビルド

```bash
dotnet build MacroPadStudio
```

VS Code では `.vscode/OshiMakiKey-Studio.code-workspace` を開きます（推奨拡張機能 C# Dev Kit、C#、PowerShell、EditorConfig のインストールが提案されます）。起動構成（通常、トレイ、サービス、ウィンドウのスナップショット、セルフテスト）とタスク（ビルド、発行、翻訳チェック、ドラッグテスト、スナップショット）が用意されています。

Visual Studio では `.vs/OshiMakiKey-Studio.sln` を開きます（「.NET デスクトップ開発」ワークロードが必要）。起動プロファイルは `MacroPadStudio/Properties/launchSettings.json` にあります。

コード内のテキストを変更したら、ロシア語パックを再生成して翻訳を確認します。

```bash
powershell -ExecutionPolicy Bypass -File tools/lang-keys.ps1
```

ポータブル exe（一時フォルダーに発行し、exe をプロジェクトのルートに置きます）：

```bash
dotnet publish MacroPadStudio -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -p:DebugType=None -o publish
```

`OshiMakiKeyStudio.exe` のコマンドラインオプション：

- `--selftest レポート.txt` — 書き込み形式（参照フレーム付き）、レイアウト、サービスキー、プリセット、テーマ・言語・ドライバーのファイル、それらがない場合の動作、テーマスクリプトのサンドボックス
- `--probe レポート.txt` — デバイスを探してドライバーを選ぶ（設定は変更しません）
- `--drop-test レポート.txt` — キー 5 の動作をノブの各側とキー 1 にドラッグ（図、一覧、Ctrl でコピー）、PASS/FAIL
- `--snapshot ウィンドウ.png [--select Key1] [--kind System] [--theme dark-blue] [--lang en] [--driver id] [--tour N] [--page settings|about|setup] [--switch-theme id] [--switch-lang コード] [--preview-theme id] [--sky-hour 0..23]` — メインウィンドウのスナップショット（ツアーの手順、ページ。`--switch-*` は開いているウィンドウのテーマや言語を変更、`--preview-theme` は開いている設定でテーマを選択、`--sky-hour` はアニメーションテーマの空の時刻を指定）
- `--form-snapshot settings0…6 | about | setup-0…2 | overwrite ファイル.png` — 単一のページやダイアログのスナップショット
- `--monitor-snapshot ファイル.png` — サンプル行入りのキーモニターのスナップショット（キーは押しません）
- `--service` — サービスのヘルパー；`--winservice` — Windows サービス（サービスマネージャーが起動）；`--install-winservice` / `--remove-winservice` — サービスのインストールと削除（管理者権限で）；`--tray` — トレイに最小化して起動

## 制限

- デバイスから設定を読み戻すことはできません。ファームウェアは書き込みのみ対応しています。
- 書き込みは USB ケーブル経由でのみ可能です。
- レイヤーは k8890、k884x、k8850 形式のみです。
- ダイレクト形式の基板はそれ自体ではメディア、マウス、連続入力に対応しません。プログラムまたはバックグラウンドサービスが必要です。
- k884x と k8850 形式は ch57x-keyboard-tool のソースから復元したもので、このプログラムでは実機でまだ確認していません。
- プログラムで明るさを変えられるのはノートパソコンの内蔵画面だけです（Windows の仕様）。

## 謝辞

プロトコルはオープンソースプロジェクト [kriomant/ch57x-keyboard-tool](https://github.com/kriomant/ch57x-keyboard-tool) と [rOzzy1987/MacroPad](https://github.com/rOzzy1987/MacroPad) を基に復元しました。テーマのスクリプトは [Jint](https://github.com/sebastienros/jint) が実行します。
